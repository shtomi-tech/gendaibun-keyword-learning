# AUTHORING_STANDARD — 語データの作成基準

> 対象: `data/set-*.json` へ語・セットを追加、または既存語の例文・語義を差し替えるときの正本。
> 前提: 例文・語義・解説はすべて書き下ろす。書籍本文は転記しない。

## 0. 追加の手順

1. セットの10語を決める（書籍のキーワード番号順。1セット＝連続する10番号）。
2. 各語について、書籍の「見出し語・番号・反（対義語）・関（関連語）」だけを一覧として控える。**定義文・解説・コラムは控えない。**
3. §2〜§6 に従って語のJSONを組み立てる。
4. §7 の検証をすべて通す。
5. 語義・例文の当否は §7「人手で守ること」で最終確認する。

## 1. スキーマ

1語のフィールド（すべて必須。`alias` のみ任意）:

```json
{
  "id": "gk01-005",
  "keyNo": 5,
  "headword": "秩序",
  "reading": "ちつじょ",
  "alias": "コスモス",
  "level": 2,
  "meanings": ["各部分があるべき位置に収まり、乱れなく整えられて保たれている状態。"],
  "notes": ["…（語の中核）…", "…（評論での使われ方）…"],
  "antonyms": ["混沌"],
  "related": [],
  "example": "自由な競争にゆだねれば、市場はおのずと一定の秩序を保つと近代の経済学は考えた。",
  "cloze": "自由な競争にゆだねれば、市場はおのずと一定の（　）を保つと近代の経済学は考えた。",
  "source": "作例"
}
```

- `id`: `gkNN-XXX`。`NN` はセット番号、`XXX` は書籍のキーワード番号を3桁ゼロ詰め。全セットで一意。
- `keyNo`: 書籍のキーワード番号。セット内で昇順。
- `headword`: 漢字表記の見出し語。`reading`: ひらがなの読み。`alias`: カタカナ別称（`コスモス`・`カオス` など、定着しているものだけ。無ければフィールドごと省く）。
- `level`: 難易度 1〜5（1がやさしい）。
- `meta`: `{ "id": "gk-set-NN", "title": "第N セット　<主題>", "count": 10, "dataVersion": 1 }`。`dataVersion` は据え置く（上げると最終チェックBESTと途中位置が消える）。

## 2. `meanings`（語義）

- **原則1文**（`check-data.mjs` が1件であることを検査する）。多義で1文に収まらない語が出たら、この規約の見直しを先に行う。
- 書籍の定義文を写さない。**同じ概念を自分のことばで**書く。
- 同一セット内の他語の語義と、4文字以上連続して一致する表現を避ける（意味重複ガードに引っかかると四択が枯れる）。対義語どうし（普遍／特殊 等）は「反対の関係」であって同義ではないので、語義が別物なら同時に選択肢へ出てよい。

## 3. `notes`（解説・補足）

- 2件を基本とする。1件目は**語の中核**（何を指す語か、どこが要点か）。2件目は**評論文での使われ方**（決まり文句、対で語られる相手、批判の文脈など）。
- 空文字不可。書籍のコラム・例文を引き写さない。

## 4. `antonyms` / `related`

- `antonyms`: 書籍の「反」。`related`: 書籍の「関」。どちらも配列で、無ければ `[]`。
- 対義語・関連語は単語カードに表示する補助情報で、両方が空の語も許容する。

## 5. `example` / `cloze`（例文と空欄）

- `example`: 40〜70字程度の**評論調1文**。書き下ろし。実在の評論を引用・改変しない。
- 見出し語（`headword` の表記そのまま）を**ちょうど1回**含める。活用や送り仮名で表記が変わらない語だけを問題にする（現代文キーワードは名詞中心なので原則問題にならない）。
- 同一セット内の他の見出し語を例文に入れない（空欄の答えが別の問題で露出するのを避ける）。
- `cloze`: `example` の見出し語1箇所を `（　）`（全角カッコ＋全角スペース）に置換した文字列。**それ以外は1文字も変えない**（`mode-vocab.js` の `exampleTargetPart` が前後一致で空欄位置を逆算する）。空欄はちょうど1つ。
- 空欄に助詞・助動詞などの付属語を含めない。

## 6. `source`

- 全語 `"作例"` 固定。`check-data.mjs` が検査する。画面にも `例文（作例）` と表示され、原典引用でないことを明示する。
- 書籍のスキャンPDF・抜粋テキストをリポジトリに置かない（`.gitignore` に `*.pdf` / `scan/`）。

## 7. 検証

追加・変更後に次をすべて実行する。

```bash
node --check static/mode-vocab.js
node --check static/meaning-guard.js
node --check static/set-progress.js
node --check static/srs.js
node scripts/check-data.mjs
node scripts/check-set-choices.mjs
node scripts/check-context-choices.mjs
node scripts/check-srs.cjs
node scripts/check-set-progress.cjs
node scripts/check-study-plan.cjs
```

### 自動で守られること

`id` の形式と一意性／`keyNo` の昇順／必須フィールドの型／`reading` がひらがな／`level` が1〜5／`meanings` が1文／`notes` が1件以上の非空文字列／`source === "作例"`／`cloze` の空欄数・連続スパン・答えの非露出・見出し語ちょうど1回／意味四択の重複ガード（`meaning-guard.js`）。

### 人手で守ること

- 語義が学説上妥当で、書籍の説明と食い違っていないこと（分かれる語義は「要確認」として残す）。
- 例文が評論の文体で、空欄の前後に語義を判断できる手掛かりが残っていること。
- 対義語・関連語が書籍の「反」「関」と一致していること。
- カタカナ別称が定着した呼称であること。
- UIに関わる変更を伴う場合は実ブラウザで確認（STEP 1〜3・最終チェックの通し、320〜375px幅、コンソールエラー、キーボード操作）。

### 意味グループ（`meaning-guard.js`）の追記

新しいセットで「字面は違うが言い換えが利く」語の組が出たら、`static/meaning-guard.js` の `meaningFamilies` に正規表現を1本足す。同じ族の語義を1問の選択肢に2つ以上出さないための仕組みで、族が0語・1語にしか当たらないうちは無害。既存の判定ロジックは変更しない。
